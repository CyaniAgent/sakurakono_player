# GetX 移除收尾计划

## 实测背景（探索已验证）

- **GetX DI 已死**：lib/ 中 0 个活跃 `Get.find`/`Get.put`/`Get.lazyPut` 消费者（ottohub bridge 仅剩 2 个防御性 `lazyPut`），所有消费方已走 `appRead(provider)`。
- **57 个文件仍 import `package:get`**，其中 13 个是纯死导入；其余分四类：`Get.parameters`(9 文件 12 处)、`Get.key.push`(3 处)、Rx 状态类型(18 文件 ~42 处)、主题 API(4 文件 12 处)，另有 2 处 `Get.to/toNamed`、6 处 `Get.delete/isRegistered`、1 处 `Obx`、2 个 `GetxService` 子类。
- **已证实的沉默炸弹**（fork 源码 + 应用代码双重核实）：
  1. `Get.parameters` 底层只由 GetMaterialApp 填充 → 恒为 `{}`，如 `/articleList` 路由 `builder: (_,_) => const ArticleListPage()` 不传参，而 `ArticleListController` 读 `Get.parameters['id']!` → 打开即崩（opus 动态卡片、scheme 链接可达）。
  2. `Get.key` 是从未挂载的 GlobalKey → 3 处 `Get.key.currentState!.push(PublishRoute(...))`（reply_controller/live_room/reply_reply）调用即崩。
  3. `Get.appUpdate()`/`Get.updateMyAppTheme()`/`Get.changeThemeMode()` 依赖 GetMaterialApp 对 rootController 的监听 → 现全为空操作 → **主题、纯黑模式、字体字重、UI 缩放的「即时生效」已静默失效**（重启才生效）。
  4. `Get.isRegistered<VideoReplyController>(tag:)`（video_host.dart:930）恒为 false → `animateToTop()` 从不执行（行为 bug）。
- 测试侧仅 2 个 ottohub 测试文件用 `Get.reset()`；`bridge_overrides_test` 的 override 计数（36）不受影响。

## Phase A — 死代码与残留清理（低风险）

1. 删除 13 个无 GetX 用法文件的 `package:get` 导入（grep 验证逐一确认）。
2. 删除 5 处 `Get.delete<X>(tag:)`（目标已是 Riverpod 管理，纯 no-op）：video_host.dart:555、live_room/view.dart:183、send_danmaku/view.dart:47、note/view.dart:51、reply_reply/view.dart:127。
3. `lib/adapters/ottohub/bridge.dart:79-81`：删除 2 个 `Get.lazyPut`（对象已由 Riverpod override 提供）；同步更新 `test/adapters/ottohub/bridge_container_test.dart`（`Get.reset()` → 普通 setUp/tearDown）与 `otto_dynamics_repository_test.dart`。
4. 删除死代码：`lib/adapters/bilibili/services/account_service.dart`（`AccountService extends GetxService` 从未实例化）+ `setting_providers.dart` 中的 `accountServiceProvider` stub；顺带修正该文件残留的 'Obtained via Get.find' 消息文案。
5. 唯一 Obx（dynamics_create/view.dart:284）：宿主 `CommonRichTextPubPageState` 的 `late final RxList<PicModel> imageList` 改为普通 `List` + 在 3 个变更点（add/removeAt/下标赋值）补 `setState()`（该类已有 setState 先例，最小 diff）。

## Phase B — 修复三类运行时炸弹（真实 bug 修复）

1. **`Get.parameters`（9 文件 12 处）**：改为 GoRouter 传参链——GoRoute builder 从 `state.uri.queryParameters` 取值 → 页面构造参数（去 const）→ 控制器构造参数。涉及：article_list、article、dynamics_topic、fav_detail（2 参数）、match_info、member_search、member_video、music、lib/pages/member。导航侧（AppNavigator.toNamed/buildUri、app_scheme、opus_content）已用 query 参数风格，无需改动。
2. **`Get.key.currentState!.push`（3 处）** → `AppNavigator.push(...)`（app_navigator.dart:148 已有现成 API）。
3. **`Get.isRegistered` 门控**：按项目既有「注册表模式」建 `videoReplyControllerRegistry`（Map<String, VideoReplyController>），reply 视图 initState/dispose 维护，`animateReplyToTop` 改查注册表 → 恢复「面板打开时才 animateToTop」的语义。
4. `Get.to(FavSortPage(...))`、`Get.toNamed(...)` 2 处 → `AppNavigator.to`/`AppNavigator.toNamed`。

## Phase C — 主题/全局刷新机制重建（修复已失效的设置即时生效）

1. 新增 `lib/utils/app_refresh.dart`：极简全局 `ChangeNotifier`（如 `appRefresh`），MyApp.build 用 `ListenableBuilder` 包裹 `MaterialApp.router`。
2. 替换全部主题类 GetX 调用：`Get.updateMyAppTheme()`（style_settings.dart 7 处、color_select.dart 4 处）→ `getAllTheme()` 重算 + notify；`Get.changeThemeMode(...)`（style_settings:661、mine/controller.dart:257）→ 已有 `ThemeUtils.themeMode` 赋值后补 notify；uiScale 对话框 2 处 `Get.appUpdate()` → notify。
3. **过渡动画设置**（判断点：`Get.rootController.defaultTransition` 已死，`Pref.pageTransition` 无任何读取点，且类型是 GetX `Transition`）：按项目「不静默删功能」惯例，定义本地过渡枚举 + 接入 `theme_utils.dart` 的 `pageTransitionsTheme`（恢复该设置生效，配合 Step 2 的刷新机制）。如你更倾向直接删除该设置行，实施时可改为移除。
4. `DownloadService extends GetxService` → 改普通类（保留 `onInit()` 语义），删除 `package:get` 依赖。
5. 删除 `lib/utils/extension/get_ext.dart`（putOrFind 无调用方）。

## Phase D — Rx 状态类型转换（18 文件 ~42 处，机械量大）

原则：**最小等价转换**，按宿主类型选机制——
- StatefulWidget State 内（common_rich_text_pub_page、download 系列页面）→ 普通字段 + setState；
- ChangeNotifier 控制器内（lib/pages/video/controller.dart、member_video_web 3 个、whisper_secondary、dyn/reaction 等）→ 普通字段 + notifyListeners（多数变更点旁已有通知）；
- pl_player 内（view/view.dart、mpv_convert_webp.dart 的 RxDouble、`data_status.dart` 的 `extension on Rx<DataStatus>`）→ ValueNotifier 或普通字段+回调，逐处确认重建链路后转换（播放器核心，谨慎、保持行为不变）。

## Phase E — 摘除依赖 + 文档 + 全量验证

1. pubspec.yaml 删除 `get` git 依赖 → `flutter pub get`；若存在传递依赖需要 get（预计没有），保留依赖但保持 lib/ 零导入并在总结中说明。
2. grep 清零验证：`package:get` 在 lib/ 与 test/ 中归零。
3. 文档同步：根 AGENTS.md（Current Phase、Architecture 树、GetX 段落删除、依赖列表、Adapter 开发示例、测试说明）；检查并更新 lib/core、lib/adapters/*、lib/pages、lib/common、lib/player 各级 AGENTS.md 中的 GetX 表述；修正「0 Obx」「No build.yaml」「~183 文件」等已过时数字。
4. 测试：`dart run build_runner build --delete-conflicting-outputs`（重建 mocks）→ `flutter analyze --dart-define=ADAPTER=bilibili` 与 `--dart-define=ADAPTER=ottohub` 双双 0 errors 0 warnings → `flutter test` 全绿（270 用例；`bridge_overrides_test` 计数不变，若有测试引用被删的 AccountService 则同步更新）。

## 执行顺序与验证点

A → B → C → D → E，每个 Phase 结束跑一次 `flutter analyze` 快速校验，全部完成后跑完整验证（E.4）。预计触及 ~55-60 个文件，绝大多数为机械改动。
